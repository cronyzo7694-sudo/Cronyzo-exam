# Deploying Cronyzo (Render + your domain)

Repo: `github.com/cronyzo7694-sudo/Cronyzo-exam` · Blueprint: [`render.yaml`](render.yaml)

**Recommended split (both free, and fast):**

| Piece | Host | Why |
| --- | --- | --- |
| Frontend (Vite build) | **Cloudflare Pages** | free custom domain, global CDN, **never sleeps**, unlimited bandwidth |
| API (Flask) | **Render free** | free Python + Postgres-friendly; kept awake by a ping (see §6) |
| Database | **Neon** (already live) | free, serverless Postgres |
| DNS / SSL | **Cloudflare** (free) | free HTTPS + proxy, works with any registrar |

> **Do not put the whole app on Render free and expect it to feel fast.** A free
> Render web service sleeps after ~15 minutes of no traffic and the next visitor
> waits **30–50 s**. Cloudflare Pages has no such thing — a static site is served
> from the edge in milliseconds. So: static frontend on Cloudflare, API on Render
> with a keep-alive ping. Total cost until you buy hosting: **₹0 + domain**.
>
> Cloudflare Pages gives you a **custom domain for free** (Render charges for
> custom domains on free instances) — that alone settles the question.

## 2. Neon (database) — already live

`DATABASE_URL` in `backend/.env` points at your Neon Postgres. Nothing to do;
Render gets the same string as an env var.

## 3. Render

1. Render → **New → Blueprint** → pick `Cronyzo-exam`.
2. Render reads `render.yaml` and asks for the `sync: false` values. Paste the
   same values that are in `backend/.env`:

| Key | Where it comes from |
| --- | --- |
| `DATABASE_URL` | Neon connection string |
| `PUBLIC_SITE_URL` | `https://your-domain.com` (after step 5) |
| `FIREBASE_PROJECT_ID`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Firebase console |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_SHOP_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | BotFather + your chat id |
| `CLOUDINARY_URL` | Cloudinary dashboard |
| `RAZORPAY_*` | leave empty — the app stays in demo mode until you paste them |
| `VITE_FIREBASE_*` | same values as `frontend/.env` |

`SECRET_KEY` and `JWT_SECRET_KEY` are generated by Render — do not paste yours.

3. Deploy. First boot creates any missing tables, seeds the landing copy and
   starts the Telegram poller. Demo inventory stays **off** (that is the
   `CRONYZO_SEED_DEMO` switch — leave it unset in production).
4. Check `https://cronyzo-api.onrender.com/api/health` → `{"status":"ok"}`.

## 4. Frontend on Cloudflare Pages (free, fast, no cold start)

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git**
   → pick `Cronyzo-exam`.
2. Build settings:

| Setting | Value |
| --- | --- |
| Framework preset | `Vite` (or None) |
| Root directory | `frontend` |
| Build command | `npm ci && npm run build` |
| Build output directory | `dist` |
| Node version | `20` (env var `NODE_VERSION=20`) |

3. Environment variables (Production **and** Preview):

```
VITE_API_URL              = https://cronyzo-api.onrender.com/api
VITE_FIREBASE_API_KEY     = …same as frontend/.env…
VITE_FIREBASE_AUTH_DOMAIN = …
VITE_FIREBASE_PROJECT_ID  = …
VITE_FIREBASE_STORAGE_BUCKET = …
VITE_FIREBASE_SENDER_ID   = …
VITE_FIREBASE_APP_ID      = …
```

4. SPA routing: on **Cloudflare Pages** add `frontend/public/_redirects` with
   `/*  /index.html  200`. On a **Worker with static assets** do the opposite —
   delete that file (Cloudflare rejects it as an infinite redirect loop,
   error 100324) and use `not_found_handling: "single-page-application"` in
   `wrangler.jsonc`, which is what this repo ships.
5. On the API (Render), set
   `CORS_ORIGINS=https://cronyzo-exam.pages.dev,https://your-domain.com`
   — comma separated, no spaces, or the browser blocks every request.

> Prefer to keep everything on Render? Uncomment the `cronyzo-web` block in
> `render.yaml` — it does the same job, minus the free custom domain and with
> no CDN.

## 5. Domain (Cloudflare — free SSL, free custom domain)

1. Buy the domain wherever it is cheapest (Cloudflare Registrar sells at cost;
   Namecheap/GoDaddy work too).
2. Add the site to Cloudflare (**Add a site**, Free plan) and change the
   nameservers at your registrar to the two Cloudflare gives you. Wait for
   "Active" (usually minutes).
3. Cloudflare Pages → your project → **Custom domains** → add
   `your-domain.com` and `www.your-domain.com`. DNS records are created for you.
4. Set `PUBLIC_SITE_URL=https://your-domain.com` on `cronyzo-api`, and add that
   domain to `CORS_ORIGINS`.
5. Firebase → Authentication → **Authorized domains** → add the domain (and the
   `*.pages.dev` host) or Google sign-in fails with `auth/unauthorized-domain`.

## 6. Keep the free API awake (this is what kills "slow")

Render free sleeps after ~15 min idle → 30–50 s cold start for the next visitor.

Fix, free: create a monitor that calls the health endpoint every 10 minutes.

- **cron-job.org** (free) or **UptimeRobot** (free, 5-min interval):
  - URL: `https://cronyzo-api.onrender.com/api/health`
  - Method: GET · Interval: 5–10 min · Expect: HTTP 200
- That keeps one instance warm 24/7 (≈744 h/month, inside Render's 750 h free
  allowance for a single service).

Without a ping the site still works, it is just slow on the first hit —
so do set it up before sharing the link with anyone.

## 6. Google sign-in on the live domain

Firebase console → Authentication → **Settings → Authorized domains** → add
`cronyzo-web.onrender.com` (and your custom domain). Without this the popup
fails with `auth/unauthorized-domain`.

## 7. Smoke test after the first deploy

1. `/` loads, hero + flag + founder photo render.
2. Google sign-in completes (no `Invalid Google token`).
3. Apply as a shopkeeper → Telegram alert on your phone → approve at
   `/admin/sellers` → the member can list a product.
4. Contact form → ticket lands in **Admin → Support inbox**.
5. Upload an image → URL is a `res.cloudinary.com` link.
6. Payments show demo mode; pasting Razorpay keys flips it to live with no code
   change.

## Free-tier notes

- The API sleeps after ~15 min of inactivity; the first request takes ~30 s.
- Neon free DB also suspends when idle — same cold-start story.
- **One gunicorn worker only** (`--workers 1 --threads 8`): the Telegram poller
  starts inside a worker, so two workers poll the same bot twice — duplicate
  replies and fought-over update offsets. Threads carry the concurrency.
- Render region **Singapore** matches your Neon database (`ap-southeast-1`);
  a mismatched region adds ~0.5 s to *every* query, and boot does a few hundred.
- Gunicorn `--timeout 180` so a cold worker boot never looks like a hang.

## Security notes (read once, apply forever)

1. **No credentials in git.** The repo is public. Seeding reads
   `CRONYZO_ADMIN_EMAIL` / `CRONYZO_ADMIN_PASSWORD` from the environment and
   generates a random password when they are missing; the demo dataset (and its
   demo logins) is off unless `CRONYZO_SEED_DEMO=1`.
2. **`/api/auth/register` cannot self-promote.** `role=admin` in the payload is
   honoured only while the database has zero admins (first-run bootstrap); every
   later request is downgraded to `student`.
3. **Rotate after any leak.** Changing the password in the DB invalidates the
   old one immediately — JWTs already issued stay valid until they expire, so
   keep access tokens short and refresh tokens revocable.
4. **The debug panel is opt-in.** `DEBUG_PANEL=1` only; a live deployment never
   publishes `/debug`.
5. **Secrets live in the host's environment**, not in the repo: Render → Environment,
   and `.env` / `render-env.txt` stay out of git (both are gitignored / outside the repo).
